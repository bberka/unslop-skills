# UI tells

Ids are stable, and reports cite them. **(L)** marks the tells `scripts/scan.mjs` can find; **(T)** marks the ones `scripts/tokens.mjs` measures. Everything else needs eyes on a screenshot or the markup.

## Template tells

These are taste calls. Each is a default that shows up regardless of subject. Any of them is fine when the brief asks for it. When nothing in the brief chose it, it is a tell.

- **ui-1 Default gradients (L).** Purple, indigo, or violet washes into blue or pink, and gradient text on one headline word. The dark-mode version is a near-black hero with a radial glow at the top and a blurred color blob behind the headline. Fix: a palette drawn from the subject. Flat color unless a gradient carries meaning.
- **ui-2 Hero formula.** Centered headline with one accented word, a subhead, a primary button plus "Learn more", and a "Trusted by" logo strip. Fix: open with the most characteristic thing in the subject's world, such as the product itself, a real screenshot, or a live demo.
- **ui-3 Card-grid sameness.** Everything chopped into identical rounded cards, including the 3-up feature grid of icon-in-tinted-circle, title, and two lines. Fix: vary the form by content. Use a list for a list, a table for comparison, and prose for an argument.
- **ui-4 One radius, one shadow (T).** The same `rounded-2xl` and `shadow-lg` on every element regardless of hierarchy. The same goes for a full pill on everything from the search field to the cards. Fix: radius and elevation that encode hierarchy, from a small defined set. A nested corner is the outer radius minus the padding between the two, so a card inside a panel is never rounder than the panel.
- **ui-5 Glass and glow (L).** Backdrop-blur panels, blurred color blobs, neon glow shadows used as decoration. Fix: remove them; use solid surfaces.
- **ui-6 Stock icons as content (L).** Sparkles, Zap, Rocket, and Shield icons, or emoji, standing in for feature illustrations, in headings, buttons, KPI labels, and feature lists. The same goes for the icon in a tinted, rounded square above each feature card, and for generic pictographs on a menu of destinations (a mountain beside "Svalbard"), where the icon says nothing the name doesn't. The scanner reports emoji once per file with the count, and each icon in a tinted tile. Fix: real product imagery, or no icon; a tinted tile goes with its icon. An icon stays when it is the control (an icon button with an accessible name), when it carries meaning the text doesn't, or when it sits in a toolbar or action menu (edit, copy, delete) where every item has one.
- **ui-7 Template chrome (L).** A "✨ New" pill above the hero, tracked-out ALL-CAPS eyebrows over every heading (also as a pill with a dot, "● FEATURES", and as a caption over a menu or dropdown list), numbered 01/02/03 markers on things that aren't a sequence, `A · B · C` meta strings, `→` appended to every link. Fix: keep only the chrome that encodes information. An eyebrow goes because the heading already names the section; numbering stays only for an order the user follows (checkout steps, an install guide). A meta string keeps the one fact the user acts on, and a fact that claims live state ("Synced", "All systems operational") has to pass the real-state test (`ui-22`). The scanner reports middle dots once per file and skips page titles ("Docs · Product"); in an app, `·` between data values ("12 players · 3 min") is information, not chrome. It reports zero-padded section numbers once per file, from two up; a single "01" is a label, three in a row over features is numbering with no order behind it.
- **ui-8 Fabricated proof (L).** "10K+ users", "99.9% uptime", invented testimonials, placeholder logos. Fix: real numbers with sources. Whether a number or a quote is true is not in the code, and cutting real proof costs as much as keeping invented proof, so don't delete or rewrite a claim you can't check: record it as a `propose` entry ("confirm the number or remove") for the owner. Cut it only when the brief or the owner confirms it is invented.
- **ui-9 Default type.** One system or Inter family at default weights with no deliberate scale, or sizes picked ad hoc. A monospace face (JetBrains Mono, Space Mono, Geist Mono) set on labels and headings because the product is for developers is the same default. Fix: a chosen family (two at most) and a stated scale. Mono is for code and for figures that must align.
- **ui-10 Studio defaults.** Cream background with a serif display and a terracotta accent; near-black with one acid-green accent; newspaper hairlines with zero radius. Fix: the same as ui-1, choose for the subject.
- **ui-11 Motion everywhere (L).** Fade-up on every section, hover-lift on every card, pulsing badges, `transition-all`, cards flying in from different sides, floating and shimmering loops, parallax, springs that overshoot on plain controls, and transitions on `width`, `height`, `top`, `left`, or margins, which reflow the page on every frame. A pulsing or shimmering skeleton is the loading affordance, not a tell. Fix: one deliberate moment, plus motion that answers a user action: a color or surface step on hover, a few pixels of travel for a menu. Animate `transform` and `opacity`, name the properties, and use one easing curve.
- **ui-12 Symmetric sameness.** Everything centered, every section the same width and padding, image and text alternating sides. Fix: hierarchy, meaning a clear primary element per screen and spacing that groups related things.
- **ui-22 Badge and tag clutter (L).** A pill, chip, or tag on every card, heading, and list row: "New", "Beta", "Pro", "LIVE", "AI", "🔥 Popular", category labels nobody filters by. The scanner reports a file from three small rounded-full labels or `<Badge>` elements up. Fix: a tag only where the reader sorts or filters by it, or where it shows state the app tracks. That is the real-state test, used here and in `ui-7` and `ui-49`: the element renders from a condition or a value (`{plan.isBeta && <Badge>Beta</Badge>}`, `status === "online"`, a prop, a query result). Markup that always renders with fixed text is decoration. Status that matters goes in words.
- **ui-23 Decorative emphasis (L).** One italic word in a headline, usually in a serif, with nothing in the sentence that calls for stress. The scanner finds `<em>` or an italic span inside `h1` to `h3`, and `italic` next to a serif or display font class. Fix: set the headline in one style. Italic is for stress, titles, and foreign words.
- **ui-24 Display-serif defaults (L).** Instrument Serif, Playfair Display, Fraunces, DM Serif, Cormorant, or Newsreader as the display face, tightened with negative tracking (`tracking-tighter`, `letter-spacing: -0.04em`). It is the 2024 template look as much as the purple gradient was the 2022 one. Fix: a face chosen for the subject, at its designed spacing. Negative tracking stays where the face is set large and the designer tuned it, which a per-heading utility class rarely is.
- **ui-25 Dividers everywhere (L).** A line between every pair of blocks: `<hr>`, `<Separator>` or `<Divider>` (menu separators included), `divide-y`, a one-pixel `h-px` or `w-px` element, a `|` or `•` between inline items, and `border-t` or `border-b` on each section, often with a border on each block as well. The scanner counts the rule elements and reports a file from three up. Side borders (`border-t`, `border-bottom: 1px solid`, `borderTop`) count toward a total of five, in stylesheets too, because a header and a footer each own one. It skips removals (`border-b-0`), side colors, and breadcrumb separators. Fix: let spacing separate. Keep a rule only where two groups would read as one without it, and never pair it with a heading or a background change that already marks the boundary.
- **ui-27 Bordered boxes everywhere (L).** Every block wrapped in `border rounded-xl p-6`, or `ring-1 ring-white/10`, so the page is a grid of outlined containers. The dark-mode version is the "glass panel" of ui-5. The scanner reports a file from five bordered, rounded, padded blocks up. Fix: boxes only around things that are objects (a card the user picks, a form). Sections, lists, and prose sit on the page.
- **ui-28 Decorative diagrams.** Node-and-edge graphs, orbiting logos, "architecture" illustrations, animated connection lines, and fake dashboards built from rectangles, placed to look technical. The more detail they carry, the less they say, because none of it is the product. The scanner flags an inline SVG from twelve shapes up as a candidate. Fix: a real screenshot, a real diagram with labels the reader needs, or nothing.
- **ui-29 Code breadcrumbs (L).** File paths (`src/components/Hero.tsx`), `~/` prompts, `$ npm install` lines, and `font-mono` labels used as decoration in a product that isn't a developer tool, or on a page that isn't documentation. Fix: remove them. A docs page shows the path of the file it is documenting and nothing else. The scanner skips `docs/` folders.
- **ui-30 Detail for its own sake.** Micro-labels on every element, four font sizes in one card, avatars, counters, status dots, and tooltips stacked on a hero, nested panels with their own headers. It reads as rich at a glance and as noise on use. Fix: one piece of information per element. Cut each decoration that the user never reads.

### Trend tells

Each of these was striking the first season it appeared and is now the fastest way to date a page to the year it was generated. None says anything about the product. They are template tells, so propose before restyling, and the fix for all of them is the same: an element drawn from the subject, or nothing.

- **ui-31 Dithering and grain (L).** Dithered or halftoned images, a noise or grain overlay on every surface (`feTurbulence`, a `grain.png` layer), and dither shaders on hero images.
- **ui-39 Heavy headings (L).** Every heading at weight 800 or 900 (`font-extrabold`, `font-black`), so the page shouts and hierarchy has nowhere left to go. Fix: hierarchy from size and color first, then weight, within two or three weights. A display face drawn to be set black stays.
- **ui-40 Stock page skeleton (L).** The same landing page for every product: hero, logo strip, three feature cards, three pricing tiers with the middle one raised under a "Most Popular" badge, testimonial cards with five stars and a round avatar, FAQ rows with a plus at the right, a closing banner that repeats the hero's button. Each section is `min-h-screen` with a few lines floating in it. The scanner reports "Most Popular" badges, five-star rows, and a file from three full-height sections up. Fix: keep the sections the product has content for, in the order a buyer asks the questions, and size each to its content. Two plans are a sentence and a table, not three cards.
- **ui-41 Dashboard filler (L).** A greeting for a headline ("Welcome back, Sam 👋"), then a row of equal stat cards, each with an icon, a sparkline, and a green "+12%" that compares to nothing, above charts with a different hue per bar. The scanner reports the greeting, outside login and sign-in pages. Fix: title the page with its context (the view or the period). A stat is a label, a figure, and a change with its baseline ("+12% vs last month"). One chart leads, with the accent on the series that matters and the rest in neutrals; a second view of the data takes another form, such as a ranked list or a short table. The charts themselves follow the chart tells (`ui-50` to `ui-54`).
- **ui-42 AI imagery.** Robots, glowing brains, circuit traces, holograms, glossy orbs, liquid chrome blobs, and a sparkle on anything a model touches, as the hero visual or the logo (a gradient tile with a sparkle in it). Also text and fake buttons baked into a generated image, and an illustration on every section. Fix: show what the product produces. Keep one visual where it explains something, usually the hero, and put real text in the page.
- **ui-32 ASCII and video backgrounds (L).** An ASCII-art render over a looping background video, or the video alone, autoplaying and muted behind the headline. Both cost bandwidth and battery to show nothing the reader can use.
- **ui-33 Grid and dot backgrounds (L).** The dotted or ruled "infinite canvas" background behind a hero or a whole page, from `bg-grid` and `DotPattern` components to the one-pixel `linear-gradient` trick. It is the stock backdrop of 2024 developer tools.
- **ui-34 Logo marquees and holographic chrome (L).** An endlessly scrolling logo strip (`animate-marquee`), and iridescent, holographic, or chrome-metal treatments on logos and headline text. A still row of real customer logos is proof (`ui-8` judges the logos themselves); the motion and the shine are decoration.
- **ui-35 Painterly backgrounds (L).** Mesh gradients, aurora washes, and impressionist or watercolor paintings blurred behind the content, usually from a shader library (`@paper-design/shaders`). They are the soft version of the gradient blob.
- **ui-36 Pixel loaders and retro type (L).** Pixel-art spinners, `image-rendering: pixelated`, and 8-bit faces (Press Start 2P, Pixelify Sans, VT323, Silkscreen) on a product that isn't a game.
- **ui-37 Squircles (L).** `corner-shape: squircle` or `superellipse`, and the `figma-squircle` and `react-squircle` libraries, applied to every corner to feel like iOS. The scanner finds them; the fix is the radius scale (`ui-4`).
- **ui-38 Text-layout showpieces (L).** Headlines that reflow, measure, or animate per glyph with a layout engine such as Pretext, `SplitText`, or a per-character `motion` stagger. The scanner finds the imports. Static type that fits is the fix. If "pretext" meant the small line above the headline instead, that is the eyebrow of `ui-7`.

## Craft tells

These are bugs. Fix them without asking.

- **ui-13 Token sprawl (L, T).** Near-duplicate colors and grays, many radii, shadows, or font sizes; raw values that bypass existing tokens; arbitrary values (`mt-[13px]`, `bg-[#5b5bd6]`). The scanner reports arbitrary values once per file with the count; `tokens.mjs` lists the distinct values. Fix: map every value onto the project's scale. Extend the scale only for a real gap.
- **ui-26 Opacity and shade stacks (L, T).** `bg-white/5`, `border-white/10`, `text-white/60`, `ring-white/20`, and `rgba(255,255,255,0.08)` as a substitute for a palette, or `zinc-300`, `-400`, and `-500` on neighboring lines. Each is a mix the reader can't name, and the UI ends up with fifteen grays. The scanner reports a file from four distinct opacity levels up, and `tokens.mjs` lists them. Fix: named surface and text tokens on the scale, and one opacity for disabled states.
- **ui-43 Unaligned figures.** Numbers in mixed formats (`$48,210` beside `$124,860.40`), proportional digits in a table column so the rows jitter, icons and labels that start on different lines from row to row, rows of one list at different heights. Fix: one number format per screen, `tabular-nums` and right alignment for columns of figures, one icon box width and one row height per list.
- **ui-14 Missing states.** Only the happy path exists. Empty, loading, error, disabled, and long-content states are missing. Fix: design each state. An empty state tells the user what to do next.
- **ui-15 Contrast (L).** Body text below 4.5:1 (large text below 3:1), such as light gray on white or a placeholder used as the label. `dark:` variants are judged against the dark background. Fix: darken to pass WCAG AA, and use visible labels.
- **ui-16 Focus removed (L).** `outline-none` (`outline-hidden` in Tailwind v4) or `outline: none` with no visible replacement nearby (a `focus-visible:` ring, or a `data-highlighted:` state on menu items), or interactions reachable only by mouse or hover. Fix: a visible `:focus-visible` style and a working keyboard path.
- **ui-17 Semantics (L).** Clickable `div`s (React `onClick`, Svelte `onclick` and `on:click`, Vue `@click`), `img` without `alt` (Svelte's `{alt}` shorthand and a props spread count as an `alt`), icon-only buttons without an accessible name, skipped heading levels, links styled as buttons that act as buttons. Fix: the native element with its name.
- **ui-18 Responsiveness.** Fixed widths, horizontal scroll at 375px, hover-only affordances, tap targets under 24px. Fix: fluid layout checked at mobile width, with targets of at least 24px (44px preferred).
- **ui-19 Reduced motion ignored (L, T).** Animation with no `prefers-reduced-motion` path. The scanner judges each file; a global rule in the base stylesheet clears every hit, and `tokens.mjs` lists which files handle it. A spinner is essential motion and is skipped. Fix: disable or shorten non-essential motion under it.
- **ui-20 Copy slop (L).** "Unlock", "Supercharge", "Elevate your workflow"; vague CTAs ("Get started", "Learn more", "Submit"); "Oops! Something went wrong"; "AI-powered" on every feature; exclamation marks in interface text; wordy placeholders ("Search anything..."); an action renamed mid-flow. The scanner reports exclamation marks in element text and in `placeholder`, `title`, and `label` attributes. Fix: name things from the user's side. A button names its exact action ("Save changes"), the same action keeps the same name through the flow, and an error says what happened and how to fix it. Inside an app screen, a section heading, card title, or caption stays at five words or fewer; a hero heading may be one sentence. Run `unslop-text` on all copy.
- **ui-21 Placeholder residue (L).** Lorem ipsum, "John Doe", "Acme", example.com, `placehold.co` images, "Feature 1/2/3". An input's `placeholder="you@example.com"` is a format hint, not residue. Fix: real content from the project, or ask.

## Copy and state tells

These are fixes, like `ui-20`: cut or shorten without asking. A good interface is used, not read, so keep the words a person needs to act and cut the rest. Deleting is the default; where a fix rewrites, it follows "Cut first, write little" in SKILL.md. Labels, buttons, tabs, table headers, and badges are fragments by design ("Last 30 days"); the sentence rules of `unslop-text` apply only to full sentences such as hero copy, descriptions, empty states, and errors.

- **ui-44 Subtitle reflex.** A subtitle under every heading, a line above the H1, or a blurb under every item of a menu, dropdown, or card list ("Greenland / Discover majestic ice fjords"). Fix: keep a subtitle only when it states a fact the heading doesn't; "Analytics / Understand your data better" loses the second line. Keep item blurbs only when the names alone can't tell the items apart (plan tiers, settings), and then only on the items that need them.
- **ui-45 Botsplaining.** Captions, helper text, and descriptions that narrate what the element visibly does: "Click the button below to get started", "This card shows your recent activity". Fix: delete. Empty states, errors, and confirmations of destructive actions stay, edited to one or two plain sentences that say what happened and what to do next, without "Oops!" or an exclamation mark ("No projects. Create a project to see it here.").
- **ui-46 Leaked design notes.** Text about how the screen works or why it was built that way: long parentheticals, "(updates in real time)", "(powered by AI)", a sentence explaining the layout. Fix: delete it, or move it to a tooltip when a user would actually look for it.
- **ui-47 Labeling everything.** A label that repeats the placeholder, the icon, the button text, or the section heading. Fix: one cue per element. In a form the visible label stays, tied to its input; a placeholder that repeats it goes (one that shows a format, "name@company.com", stays), and so does helper text that restates the label or the field's obvious purpose ("We'll use this email to contact you"). A constraint the user can't guess ("At least 12 characters") stays. A search field with a magnifier icon takes a placeholder or a label, not both.
- **ui-48 Staccato and empty slogans.** "One. Big. Thing.", "Built different.", "Ship faster. Think less." Fix: one sentence that names the thing and what it does, in words the page already uses, or delete.
- **ui-49 Status dots without state (L).** Small colored or pinging dots (`h-2 w-2 rounded-full bg-green-500`, `animate-ping`) beside text, saying "live" or "online" when nothing is bound to them. The scanner reports small round elements and pings; a pulsing element is `ui-11`, and a pulsing loading skeleton is neither. Fix: keep a dot only when it passes the real-state test (`ui-22`), and give it an `aria-label`; otherwise remove it with any "Live" word next to it.

## Chart tells

Fixes, like the copy tells. They change the words and the scaffolding of a chart, never its type, data, or series colors.

- **ui-50 Chart titles that name the chart type (L).** "Bar chart of monthly revenue", "Line graph showing signups". Fix: name the quantity ("Monthly revenue"). When the data is fixed (a report, a static figure) the title can state the finding instead ("Revenue doubled since March"); a chart fed by live data keeps the neutral title, because a finding goes stale.
- **ui-51 Reading instructions (L).** Captions that explain how to read the chart: "Each bar represents one month", "Hover over a point to see the value". Fix: delete. The scanner reports one per line.
- **ui-52 Saying it twice.** One quantity with several encodings: a bar, a value printed on it, a gridline at its height, and an axis tick all giving the same number; a KPI with an arrow, a percent, the word "up", and a sentence under it ("Revenue grew 12% compared to last month"). Fix: one encoding per job. Axis and gridlines show shape; a printed value goes on the number that matters (often the last point or the maximum). A KPI keeps its figure, one direction cue, and its baseline ("▲ 12% vs last month").
- **ui-53 Chart scaffolding (L).** A frame around the plot area, dark or thick gridlines, minor ticks, heavy axis borders, 3D, drop shadows and glows on marks, a fill behind the plot. The scanner reads chart configs in `.js`, `.ts`, and `.py` files as well as markup: `drop-shadow`, `shadowBlur`, `minor:` ticks, and `border` or `grid` widths of 1.5 or more. Fix: delete it, or make what must stay (a few gridlines, one baseline) a light-gray hairline. Data on top, labels next, scaffolding faintest.
- **ui-54 Legend where a direct label works (L).** A legend box that makes the reader match colors to names when the name could sit at the end of the line or beside the bar. The scanner reports enabled legends (`legend: { display: true }`, `<Legend>`, `ax.legend()`). Fix: label each series directly, ideally with its latest value ("This year 1,150"), and drop the legend. Keep a legend for more than four series or marks too close to label.

## Product tells

These are decisions nobody made. The screen has the parts other apps have, wired the way each prompt asked, and nothing in it came from what this user is doing. They apply to app screens, not marketing pages. Every fix adds or removes behavior, so each finding is a `propose` entry, and no file changes until the user agrees.

- **ui-55 Borrowed parts.** An element that is there because other apps have one: the account email heading a menu when there is one account to be in, a workspace switcher with one workspace, a Help row beside a help icon, a notification bell nothing feeds, a Settings page with nothing to set. The original had a reason (the email tells a user with three logins which one this is), and the copy kept the part without it. Check each item of a menu, toolbar, or popover: name the question it answers or the task it starts for this user on this screen. An item that offers a choice or shows state has to pass the real-state test (`ui-22`): the switcher renders from a list that can hold more than one. A menu that would be item for item the same in an unrelated product fails the swap test. Fix: propose removing the part. Propose a replacement only for something the source already has (a route, a handler, a field on the model), such as an away status in a task tracker that stores one.
- **ui-56 Work left to the user (L).** A control that was simple to build and leaves the working-out to the person using it: day, month, and year selects for a date near today, so picking "this Friday" means counting days; a text field for a value the app holds a list of (an assignee, a project, a time zone); a raw id to paste; a question the app can already answer (the email again, a currency the account has set). Complexity doesn't disappear when the control gets simpler; the user carries what the system dropped. The scanner reports a file that holds day, month, and year selects, and skips any file that asks for a date of birth. Fix: propose the control that does the work. A near date takes the project's date picker, or `<input type="date">` when it has none, and still accepts typing. A value from a known list takes a picker or autocomplete over that list. A known value becomes the default. Three fields stay for a date of birth or any date years away, which nobody reaches by paging a calendar.
- **ui-57 Tour instead of setup (L).** A first-run modal of slides, a coach-mark tour, or a "Welcome to" carousel that explains the app and changes nothing in it. The user clicks through and lands on the same empty screen with the same question: what do I do first. The scanner reports tour libraries (`react-joyride`, `shepherd.js`, `intro.js`, `driver.js`, `reactour`) in markup and in plain modules, onboarding modal components, and "Skip tour" buttons. Fix: propose removing the tour and letting each empty state name its first step (`ui-14`). When the first run needs answers only the user has (which features, who is on the team), propose a setup that asks for those, ends with their first real object created, and says the choices can be changed later. A tour the user starts from a help menu stays, and so does a first-run flow that already collects answers and creates the first object, whatever its component is called: both are `keep` entries.
- **ui-58 Sidebar-only navigation.** Every page hangs off the sidebar and none links to another, which is what one page per prompt produces. A task page prints its project, owner, and sprint as plain text while each has a detail route, so "who else is on this project" costs a trip to the sidebar, the list, and the row, and loses the task. Check each entity name on a detail page or in a table row (`{task.project.name}`) against the router. Fix: propose making the name a link to its page, with the project's own link component. A hover preview is an optional extra, never the only way in: the link works by keyboard and touch (`ui-16`, `ui-18`), and the preview shows only what the current page's task needs (seen from a task: a project's status, team, and assignees).
